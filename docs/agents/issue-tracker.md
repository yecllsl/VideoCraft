# 工作项跟踪

本仓库使用**本地 Markdown** 作为 issue tracker：工作项以 `.scratch/<主题>/` 下的文件管理，该目录由根 `.gitignore` 排除，**不进 Git**。代码与文档托管在公开仓库 `yecllsl/VideoCraft`（2026-11-11 历史重写后），GitHub 只是分发渠道，不是 tracker；外部 PR 不作为 triage 请求面。

## Conventions

- 一个主题一个目录：`.scratch/<主题>/`，目录内 `progress.md` 是台账。
- 每项工作一个独立文件 `NN-<slug>.md`（如 `01-auth-architecture-decision.md`），记录目标、验收条件、依赖与标签。
- PRD 单独成文时沿用本仓库已有的小写 `prd.md`；不强制 `PRD.md`，也不另建 `issues/` 子目录。
- 状态用文件顶部的 `- **标签：** \`xxx\`` 行记录（见 `triage-labels.md`）；`progress.md` 的 `- [ ]` / `- [x]` 表示完成度。
- 对话与 triage 备注追加到文件末尾 `## Comments` 段；`/triage` 写入的每条备注必须以 `> *This was generated by AI during triage.*` 开头。

## When a skill says "publish to the issue tracker"

在 `.scratch/<主题>/` 下新建对应文件（目录不存在时创建），并在该主题 `progress.md` 的工作项列表登记一行。不要调用 `gh issue create`。

## When a skill says "fetch the relevant ticket"

读取所给路径或编号对应的 `.scratch/<主题>/NN-<slug>.md`；用户通常直接给路径或编号。
