# VideoCraft 剪辑工作目录实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：**配置安全隔离的 NAS 存储映射、向远程 MCP 提供严格字幕生成，并在 Windows 工作目录建立可审批的首个样例剪辑流程。

**架构：**开发和测试环境分别挂载相同三类 SMB 共享，raw 只读、projects/output 可写但按环境分区；远程字幕工具复用现有严格对齐实现，先在开发验证再部署测试。Windows 侧使用工作流 skills 编排只读盘点、用户审批、字幕审阅和远程合成。

**技术栈：**Linux CIFS 挂载与 VideoCraft 本地配置；Python 远程 MCP 和现有字幕核心；OpenCode MCP 工具；Markdown 工作流 skills；Windows SMB。

**设计说明：**`docs/superpowers/specs/2026-11-04-videocraft-workflow-design.md`

## 全局约束

- 原始素材共享 `raw` 只读；远端原始媒体不复制到 Windows。
- 开发环境 `/root/projects/videocraft/` 先实现、验证；测试环境 `/opt/videocraft/` 只在开发验证通过后部署。
- `projects` 与 `output` 下的开发、测试文件分别位于 `dev/`、`test/`；写入使用独立项目目录和唯一文件名，不覆盖已有文件。
- 字幕以确认文案为准、以录音为时间轴；自动转写仅供参考，低置信对齐等待人工确认。
- 不提交分镜合成，直到用户确认素材对应表；不自动配音、不默认添加配乐、不烧录首版字幕。
- 远程字幕工具每次只处理一个口播视频；不修改源媒体、不负责文案生成或视频合成。
- 所有凭据必须使用既有安全凭据机制；不得写入仓库配置、日志或 shell 历史。

## 文件与配置责任

- 修改开发与测试环境的 `videocraft.local.toml`：只声明各自的 raw/projects/output 挂载根。
- 修改现有部署配置（先查明 `fstab`、systemd mount 或项目既有机制）：管理三共享挂载、权限和依赖顺序，不另造第二套机制。
- 更新各环境 `/.../assets` 软链：指向核实后的原始素材根，保持本地 CLI 与远程 URI 根语义一致。
- 修改开发仓库中远程 MCP 工具注册/实现模块及对应 `tests/test_remote_tools.py`、必要的存储/协议测试：新增单段严格字幕工具。
- 修改开发仓库的 `docs/`、`AGENTS.md`、`skills/`：登记远程工具契约及开发/测试部署说明，确保项目文档与行为一致。
- 修改 Windows 工作目录 `AGENTS.md` 和新增 `.agents/skills/` 下的本地工作流 skills：定义审批闸门、MCP 工具路由、产物记录。
- 创建 `projects/宝马5系2/` 的轻量记录：素材对应表、逐段确认文案/字幕审阅记录、任务状态与输出引用；媒体仍在 NAS。

## 重点检查

- **共享名、凭据或挂载策略与假设不同：**先停止对应挂载变更，验证后修订配置；测试为挂载单元/配置检查拒绝不完整配置。
- **NAS 暂时不可用或挂载点退化为本地目录：**写操作必须失败而非写入本地目录；测试为卸载/错误来源状态下的写入门禁检查。
- **字幕输入路径越权、输出 URI 指向 raw、路径穿越或目标已存在：**拒绝写入且不触碰源/既有文件；测试覆盖上述 URI 类别。
- **确认文案与录音不匹配、音轨缺失或对齐告警：**输出结构化告警并标记人工确认，不把不可靠结果当作合格字幕；测试覆盖无音轨和无法对齐输入。
- **素材对应表尚未获用户确认：**工作流不得调用 `submit_assemble`；测试以审批状态门禁验证工具调用被阻断。

### 任务 1：核实挂载方案与 `assets` 路径语义

**文件/环境：**只读检查开发、测试挂载配置和工具路径；此任务不写远端文件。

**接口：**产出已核实的三个 SMB share 名、凭据引用机制、挂载持久化方式、挂载用户/权限，以及本地 CLI 和远程 MCP 对 `assets`/`storage.roots` 的实际路径要求。

- [ ] 检查 Windows `\\192.168.100.58\` 下 projects/output 的精确共享名，确认共享 ACL 和现有 SMB 访问方式。
- [ ] 检查两环境挂载表/单元、`videocraft.local.toml`、`assets` 消费点及远程存储解析代码；区分已存在配置与本地目录。
- [ ] 验证凭据存放位置不输出秘密，确认三个挂载是否能以只读 raw、可写 projects/output 的权限挂载。
- [ ] 根据证据更新 spec 中未确定项；若 share 名或权限不符合设计，暂停任务 2 并请求用户决定。

### 任务 2：配置开发环境 NAS 根与软链

**文件/环境：**开发 `/root/projects/videocraft/videocraft.local.toml`、已确认的挂载配置和 `assets` 软链。

**接口：**开发 `raw=/mnt/nas/raw`、`projects=/mnt/nas/projects`、`output=/mnt/nas/output`；`assets` 解析到本地流程要求的 NAS raw 路径；开发可写数据只能进入 `dev/`。

- [ ] 在开发仓库可运行的配置验证测试/命令中加入三根路径与只读/可写预期检查；先运行并确认当前配置失败或缺失。
- [ ] 添加开发挂载配置，使用任务 1 核实的现有凭据机制；raw 以只读方式挂载，projects/output 按设计可写。
- [ ] 在 `videocraft.local.toml` 配置三根存储路径；确认未知键/必需键检查通过。
- [ ] 将 `assets` 软链调整到核实的目标；挂载顺序需保证 assets 不会在 NAS 未挂载时解析到空本地目录。
- [ ] 验证三处 `findmnt` 来源/类型、raw 写入拒绝、projects/output 的 `dev/` 临时文件创建并清理、CLI selfcheck、`assets` 实际解析；任何失败立即停止后续开发环境写入。

### 任务 3：配置测试环境 NAS 根与软链

**文件/环境：**测试 `/opt/videocraft/videocraft.local.toml`、已确认的挂载配置和 `assets` 软链。

**接口：**与任务 2 相同的挂载点和权限；测试可写数据仅进入 `test/`。不得覆盖测试环境已有项目或输出。

- [ ] 运行只读盘点，确认测试共享 `projects/test/`、`output/test/` 下的现存内容，记录基线。
- [ ] 添加/修正测试三共享挂载和存储根配置；保留已运行 MCP/Worker 服务，不重启服务直到配置及挂载验证完成。
- [ ] 更新测试 `assets` 软链并确认挂载依赖，raw 仍只读。
- [ ] 验证 `findmnt`、selfcheck、SMB 双向可见性、raw 写入拒绝及在唯一临时路径上的 projects/test 与 output/test 写读；与任务 2 不同的 mount 来源或权限必须视为失败。
- [ ] 确认当前服务加载配置的方式；仅在需要且经安全维护步骤批准时安排受控重启，重启后验证 MCP/Worker health 和六工具清单。

### 任务 4：在开发环境向远程 MCP 暴露严格字幕

**文件：**开发远程 MCP 工具注册与实现模块；`tests/test_remote_tools.py` 及存储/协议测试；开发 `AGENTS.md` 与字幕技能文档。

**接口：**新增工具 `strict_subtitles(video_uri: str, text: str, output_uri: str) -> dict`。只接受 `nas://raw/` 视频输入和 `nas://projects/` 下、位于 `dev/` 的 `.srt` 输出；输出含逻辑 URI、cue 统计和现有严格字幕算法产生的告警/状态。

- [ ] 编写远程工具测试：有效调用委派给现有 `strict_subtitles` 核心并写出 SRT；不调用 assemble；输出为 `nas://projects/` URI。
- [ ] 编写拒绝测试：raw 输出、projects 外路径、`..` 路径穿越、空文案、非视频输入、无音轨、已存在目标；确认拒绝前后文件状态不变。
- [ ] 运行上述测试确认新增工具未注册/实现前失败。
- [ ] 以最小适配接入核心算法，使用服务端 StorageResolver 安全解析 URI；通过临时文件或互斥创建保证不会静默覆盖目标，清理失败的临时产物。
- [ ] 注册工具并验证 MCP 工具 schema 与错误返回为稳定、无秘密的结构化结果。
- [ ] 运行远程工具、存储解析、协议和回归测试；开发环境 selfcheck 通过。
- [ ] 在开发 NAS `projects/dev/宝马5系2/` 生成一份唯一命名的测试 SRT，检查字幕 cue、时间范围、告警、SMB 可读性；不提交合成。

### 任务 5：部署并验收测试环境字幕工具

**文件/环境：**仅在任务 4 全部通过后部署 `/opt/videocraft/` 对应代码与测试服务配置。

**接口：**测试 MCP 新工具 schema 与开发一致；输出路径限定在 `projects/test/`；现有 6 工具保持可用。

- [ ] 记录测试部署前代码版本、服务状态、工具清单及现有项目/输出目录基线。
- [ ] 将经验证的变更部署到测试环境，不同步开发本地配置、密钥或 dev 产物。
- [ ] 按服务既有流程重启必要组件；核验 Worker/MCP health、工具总数与工具 schema。
- [ ] 对样例单段调用字幕工具，输出到唯一的 `projects/test/宝马5系2/` SRT；从 Windows SMB 打开并核对内容，不提交 assemble。
- [ ] 验证测试工具拒绝越权 URI 和目标覆盖；确认既有 test 项目/输出基线未改变。

### 任务 6：建立本地剪辑工作流 skills 与样例记录

**文件：**Windows `AGENTS.md`、`.agents/skills/` 工作流 skills、`projects/宝马5系2/` 轻量记录。

**接口：**技能明确素材审批、SRT 审阅和合成授权的先后关系；样例记录引用 `nas://` URI，不包含媒体文件。

- [ ] 按现有本地 skill 机制选择最少的技能集合，并读取 `SKILL-MECHANICS.md`；描述只列出可独立触发的分支，优先 user-invoked 以避免无关上下文加载。
- [ ] 编写素材盘点/对应表技能：调用 probe/extract_frames 只读分析，输出规定字段，明确只有用户确认后审批状态才能变为已确认。
- [ ] 编写字幕生成/审阅技能：逐段调用远程工具，SRT 由 SMB 审阅；告警或不匹配时暂停，不宣称字幕确认。
- [ ] 编写合成/交付技能：只有确认对应表后调用 `submit_assemble`；采用 1080p/60 fps、旁挂字幕、独立任务和唯一输出，轮询状态并记录任务 ID。
- [ ] 在 Windows `projects/宝马5系2/` 建立素材清单和审批表模板，按编号列出 8 个已盘点素材 URI、时长/流信息；文案、空镜时间区间和匹配理由留待画面审阅，不虚构判断。
- [ ] 运行技能文档检查：所有 MCP 工具名与 schema 一致；审批前不得提交任务；所有媒体路径为 NAS URI；目录中没有媒体副本。

### 任务 7：只读画面审阅并交付对应表待确认

**文件/环境：**Windows `projects/宝马5系2/` 素材对应表；输入为 NAS raw 视频。

**接口：**逐段对应表包含话术编号、文案范围、空镜素材及起止、匹配理由、口播画面处理和待确认项；状态保持“待用户确认”。

- [ ] 对五段话术和三段空镜执行少量抽帧预览；仅用帧和只读 probe 结果，不下载视频副本。
- [ ] 基于实际画面与用户提供/确认文案填写候选对应表；未获文案时只标记需补充，不推测台词。
- [ ] 将对应表交用户审阅；此任务结束时不得调用 `submit_assemble`，不得把审批状态写成已确认。

## 执行顺序与外部确认

任务 1 是挂载变更前置条件；任务 2、3 依次独立验收；任务 4 仅在开发环境工作；任务 5 必须等待任务 4 全部通过；任务 6 可在字幕开发期间准备但不得触发远程写操作；任务 7 等工具与 SMB 项目根可用后执行。素材对应表确认后，另开实施任务提交分镜草稿，不在本计划内自动渲染。
