# VideoCraft MCP 环境设计

## 目的

让当前 Windows 工作目录默认连接现有测试 MCP 服务，同时保留一个明确、按需使用开发目录的途径；认证凭证不保存在项目配置中。

## 目标

- 测试环境 `/opt/videocraft/` 的 MCP 与 Worker 服务保持运行且不作改动。
- 开发环境 `/root/projects/videocraft/` 不配置为开机常驻服务；仅通过客户端显式启动 SSH stdio MCP。
- 将本目录 `opencode.json` 中的明文令牌改为 OpenCode V2 环境变量引用 `{env:VIDEOCRAFT_MCP_TOKEN}`。
- 验证测试 MCP 连通性及开发入口配置，不调用会写入媒体或提交剪辑任务的工具。

## 非目标与约束

- 不停止或重启任何服务，也不终止当前由 VS Code 管理的 MCP 进程。
- 不修改任一远程代码目录、systemd 单元、防火墙、测试 Worker 或 NAS 数据。
- 不配置开发 HTTP 监听：目前观察到的开发 MCP 使用 stdio，且开发目录没有本地部署 TOML 配置。
- Windows 令牌保存为当前用户环境变量，不写入本项目或任何提交文件。

## 方案比较

- **只复用测试 HTTP 服务：**最简单，但没有专门的开发环境入口。
- **增加开发 HTTP 服务：**不采用。开发目录目前没有部署配置，采用该方案需要额外决定端口、监听地址及部署方式。
- **推荐：**测试 HTTP 服务仍作为默认入口；为开发目录添加一个默认禁用、需要时显式启用的 SSH stdio MCP 配置。此方案符合已观察到的传输方式，也不会增加常驻监听端口。

## 预期行为

项目配置中的 `videocraft-remote` 继续连接 `http://192.168.88.4:8000/mcp`，从 `VIDEOCRAFT_MCP_TOKEN` 读取 Bearer 令牌，并保留必需的 Host 请求头。另设独立的开发 MCP 入口，通过 SSH 调用开发目录中的 MCP 启动脚本，且默认禁用；只有用户有意启用时才启动。若远端进程需要环境变量，应由 SSH 启动命令传入，过程中不得打印秘密值。

## 待验证事项

启用开发入口前，先确认现有启动脚本能否读取开发目录当前配置，以及 OpenCode V2 是否能用本地 stdio MCP 配置表达该 SSH 启动方式。如果不修改远端配置或代码就无法验证，则不改远端主机；保留测试环境配置，并报告阻碍项，必要时仅提供显式手动 SSH 启动命令。
