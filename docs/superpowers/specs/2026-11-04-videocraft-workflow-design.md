# VideoCraft 工作目录与剪辑流程设计

## 目标

将当前 Windows 目录完善为通过 VideoCraft 远程 MCP 进行 NAS 素材剪辑的工作目录，并为首个样例 `宝马5系2` 建立可审阅、可追踪的口播与空镜剪辑流程。

## 已确认的工作流

- 首个样例素材位于 `\\192.168.100.58\videocraft-raw\宝马5系2\`，包含 5 段口播视频和 3 段空镜视频。
- 复用 NAS 原始素材；Windows 工作目录只存轻量计划、素材对应表、审阅记录和 MCP 任务编号，不复制媒体。
- 口播视频画面作为主画面，在用户确认对应关系后穿插空镜；话术文件按编号顺序处理。
- 录音是最终语音来源；确认文案决定字幕文字，录音决定字幕时间轴。自动转写只作为初稿或校对参考；低置信对齐须报告并等待确认。
- 每次字幕工具调用处理单段口播视频、该段确认文案，并输出到 `nas://projects/` 下的独立 SRT。
- 先生成逐段素材对应表，至少列出话术编号、文案范围、空镜文件和使用区间、匹配理由、口播画面处理、待确认项；用户确认后才提交分镜。
- 首版仅用现有口播录音；配乐仅按用户明确要求添加。
- 默认 1080p、25 fps；先交付旁挂 SRT 草稿，预览检查并经用户确认后再决定烧录或精修。
- 成片、项目文件和任务中间文件存 NAS；Windows 通过 SMB 审阅 NAS 项目目录中的 SRT。

## 环境与存储约束

- 开发环境为 `/root/projects/videocraft/`，测试环境为 `/opt/videocraft/`。
- 三个共享分别映射到 `/mnt/nas/raw`、`/mnt/nas/projects`、`/mnt/nas/output`；`raw` 只读，`projects` 和 `output` 可写。
- 开发和测试可共享只读 raw；可写项目与输出在共享内按 `dev/`、`test/` 隔离，输出名唯一，不能覆盖已有成果。
- `assets` 软链须指向本地流程预期的原始素材根；实施前核实本地工具如何解析该软链以及远程服务如何使用 `storage.roots`。
- 当前已知：开发、测试两环境的三个挂载点均活动，分别映射 `videocraft-raw`（只读）、`videocraft-projects`（读写）、`videocraft-output`（读写）；测试配置已有三根 storage roots，开发未配置；两边 `assets` 均指向 `/data/media`。Linux 挂载由 systemd 从运行时 mountinfo 导入，未发现 fstab 或持久化 mount unit；当前挂载来源/重启后恢复机制尚未查明。客户端挂载使用 CIFS 3.0、账号 `drche`，服务以 UID/GID 999/996 运行；这并不证明 NAS 服务端 ACL 或有效写入权限。持久化来源及有效权限须在配置变更前查明。

## 远程字幕能力

- 测试代码已有 `strict_subtitles` 算法，但远程 HTTP MCP 目前只暴露 6 个工具，未暴露该能力。
- 在开发环境实现远程工具适配并复用现有算法，再验证后部署到测试环境；不从头重写对齐算法。
- 工具仅处理单段：输入 `nas://raw/` 口播视频 URI、确认文案、`nas://projects/` SRT 输出 URI；读取音轨并写出旁挂 SRT，不改文案、不改源视频、不合成视频。
- 工具须验证 URI 根、输出父目录、输入类型、文案和目标文件行为；不得允许写入 raw 或静默覆盖既有文件。具体对齐质量告警须遵循现有严格字幕实现的报告格式。
- Windows 用户可通过 `videocraft-projects` SMB 共享查看并编辑 SRT；最终分镜使用已确认字幕内容/文件。

## 工作目录技能

创建面向本地工作目录的中文工作流 skills，按职责分开素材盘点/对应表审批、严格字幕生成/审阅、分镜提交/草稿检查与交付记录。技能仅调用已配置的 MCP 工具和明确允许的只读操作；任何媒体合成提交必须发生在素材对应关系经用户确认之后。

## 非目标

- 不上传或复制原始媒体到 Windows。
- 不在未确认对应表时提交合成任务。
- 不加入自动配音、自动替换口播或默认配乐。
- 不在本阶段烧录字幕或制作最终精修成片。
- 不把测试环境用于开发验证；开发实现与验证先完成，才部署测试。
