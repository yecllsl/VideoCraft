# VideoCraft MCP 预检与素材发现设计

## 意图

让客户端能在剪辑前按既定工作流完成环境预检、发现指定 raw 项目中的素材、核验 test 命名空间存储边界，并记录输出目录既有文件基线。当前 `videocraft_selfcheck` 能报告 core、存储根与 Worker，但不报告 NVENC；现有工具没有目录列举或存储权限探针，因此无法安全启动一个新项目的素材盘点。

## 目标

- 自检明确报告 core、三个根的健康状态、Worker、NVENC、工具面和配置的字幕写入 namespace，并区分“不支持/无法检测”与失败。
- 新增只读目录清单能力，支持按逻辑 URI 列举允许范围内的目录和媒体元数据，不暴露服务端物理路径。
- 新增显式、受限的存储权限探针：确认 raw 不可写；在 projects/test 与 output/test 各自独立创建、读取、删除唯一探针对象，并报告每步结果及清理状态。
- 可读取 `nas://output/test/<project>/` 文件清单及轻量元数据，供客户端记录覆盖前基线；操作只读且限定项目目录。
- 客户端流程在所有要求项通过前不生成最终字幕、不提交合成；失败时准确指出组件、逻辑根和失败阶段。

## 非目标

- 不变更字幕对齐、合成、Worker 调度或视频编码行为。
- 不允许 raw 写入，不提供任意文件读写、删除、移动或覆盖 API。
- 不将服务端绝对路径、凭证、令牌或敏感异常内容返回客户端。
- 不自动确认素材对应表，不自动生成最终字幕或提交合成。
- 不将探针结果解释为 NAS ACL 的普遍保证；结果仅代表当前服务身份、挂载状态与探针时刻。

## 约束

- 测试环境为 `/opt/videocraft/`，开发环境为 `/root/projects/videocraft/`；先开发环境实现与验证，再部署测试环境。
- 继续使用逻辑 URI 与 storage resolver 的边界检查；客户端不复制媒体。
- raw 只读；projects/output 写入限制在配置的 `test` namespace。
- 当前会话没有可用的远程代码执行/SSH 通道；实施前须在对应服务端开发 checkout 中检查实际 MCP 路由、存储 resolver、配置与测试结构，不可臆测代码位置或实现接口。

## 方案

1. **分离的最小能力（推荐）**：扩展 `videocraft_selfcheck` 的环境能力报告；新增只读目录/媒体清单工具；新增显式存储权限探针工具。各工具职责单一，权限容易审核，客户端可按顺序组合工作流。
2. 单一项目盘点工具同时返回 raw 清单、输出基线、NVENC 和写权限探针。调用简便，但把多种权限、耗时和部分失败语义耦合进一个响应，难以单独审计和重试。
3. 继续通过 SSH/人工命令盘点。不改 MCP，但当前客户端缺少可验证的 SSH 执行通道，且无法让工作流自动确认工具能力，不满足目标。

选择方案 1：其职责和失败边界最清楚；对现有字幕与合成工具没有破坏性变更。

## 建议接口与行为

### 1. 自检扩展

保留现有字段和兼容性，增加结构化 capability 结果：NVENC 为 `ok`、`unavailable` 或 `error`，附不含敏感值的诊断原因；服务端注册工具清单；字幕写入 namespace。不得仅因无法探测就报告 NVENC 健康。环境中确实不使用 NVENC 时，明确报告 `unavailable`，由工作流按目标任务判定是否阻断。

根健康状态、Worker 状态仍独立呈现。不可达、认证失败、服务未启动和根未挂载等可区分错误应由 MCP transport/HTTP 层与 selfcheck 结果共同提供；不得将认证秘密放入错误文本。

### 2. 只读目录与媒体清单

新增只读逻辑 URI 列举能力，仅接受允许的 raw 项目路径和 test 下的项目输出路径；默认不允许列举 storage 根、父目录或跨 namespace。支持分页/上限，返回逻辑 URI、类型、大小、修改时间（若可靠可得）及媒体文件探测元数据；不递归无限扫描，不返回物理路径。应拒绝路径穿越、符号链接越界、未知 scheme、未授权 namespace 和非目录 URI。

客户端用 raw 项目清单盘点素材；用精确 `nas://output/test/<project>/` 清单记录既有文件基线。projects 目录清单可用于核验字幕项目现状，但不得读取任意内容。

### 3. 存储权限探针

显式调用，不由每次普通 selfcheck 隐式执行。固定检查 raw 写入被拒；对 projects/test 和 output/test 分别在专用隐藏/保留探针目录下创建不可预测唯一文件、写入固定无敏感内容、读取并比较、删除，并验证删除后不存在。探针目录应由服务端定义且不能与用户项目路径冲突；不得清理或覆盖任何既有对象。每个阶段单独返回 `passed`/`failed`/`not_run`，失败后尽力清理本次精确创建的对象并报告残留逻辑 URI。重复请求使用不同随机 ID，不能重用/覆盖旧对象。

若底层无法安全证明目标不存在或创建为独占操作，则停止该根探针并报失败，不得退化为覆盖式写入。raw 的拒写验证必须使用安全的边界/配置检查或针对专用随机目标的受控拒绝操作，绝不尝试覆盖/删除现有 raw 文件。

## 安全与兼容性

- 新增工具默认随版本注册；客户端应检查工具存在与 schema 版本，不存在时阻断初始化并给出升级提示。
- 所有文件访问复用现有 URI resolver 和 namespace/root guard；禁止直接拼接物理路径绕过 resolver。
- 输出清单与探针仅在调用者当前授权范围内执行，限制条目数、路径深度、响应体大小和执行时间。
- 只返回必要错误信息；服务端日志不得记录 bearer token 或完整环境变量。
- 保留现有工具响应字段，新增字段采用可选、向前兼容形式；新增工具错误码稳定并可区分 `INVALID_URI`、`PERMISSION_DENIED`、`ROOT_UNAVAILABLE`、`OUTPUT_EXISTS`、`PROBE_CLEANUP_FAILED`、`LIMIT_EXCEEDED`。

## 验收条件

- 单元测试覆盖 selfcheck 能力字段的成功、不可用、失败状态及 namespace/tool 清单。
- 目录列举测试覆盖 raw 项目成功、test 输出项目成功、分页/上限、非目录、越界 URI、路径穿越、链接逃逸、错误 namespace、不可用根与权限拒绝；验证无物理路径泄漏。
- 权限探针测试覆盖每阶段成功、创建冲突、读回不符、权限拒绝、根不可用、异常清理，以及绝不改动预存对象；成功探针结束后无残留。
- 集成验证在开发环境以真实 NAS 身份跑通三个根行为（raw 拒写、projects/output 独占写读删），并记录精确结果；测试环境部署后重复验证。
- 使用新项目 `宝马5-20261106` 验证能列出 raw 素材和 output 基线；本任务只做初始化验证，不生成字幕、不提交合成、不改变既有输出。
- 客户端工作流在任何必要预检项失败或工具缺失时停止，提示具体未通过项目；通过后能将返回清单整理为本地素材清单与既有输出基线。

## 留给实现者的决定

- 在阅读现有 MCP 注册与 resolver 代码后确定工具命名、schema 版本和分页游标格式。
- 在真实环境核查挂载目录是否支持安全的独占创建和删除后，确定专用探针目录布局；不得预先假定 NAS 语义。
- NVENC 检查优先复用项目既有自检/编码器探测；若部署实际采用 CPU 编码，返回明确 `unavailable`，由工作流规则决定是否阻断，不伪造成功。
- 服务端开发 checkout、远程测试部署及权限探针需要合适的远程执行通道和授权；本设计不自动授权对远端的操作。
